## 本轮实际验证

环境：Linux/WSL，Python 3.14.4。核心脚本只使用 Python 标准库。

| 检查 | 结果与范围 |
|---|---|
| 模板静态校验 | 通过；大小预算、配置和模板链接有效 |
| 写入分类与守卫回归 | 通过；含失败工具不认写入、重要修改缺交接阻塞、重复拦截有上限 |
| 项目分发器回归 | 通过；含嵌套目录、Windows/WSL 路径形状、其他发行版跳过与非协议目录跳过 |
| 最新交接观察回归 | 19 组通过；含真实内联 Python 更新、无变化不记账、失败结果不认可、其他会话不冒领与重复 Stop |
| MCP 内部自检 | 通过；使用已接入的临时项目确认当前任务表问题数为 0 |
| 首次接入与预览 | 在一次性、含空格的目录通过；`--dry-run` 不创建目标，实际接入后校验通过 |
| 重复接入 | 同一干净临时项目二次运行后，所有文件内容逐字节不变 |
| 已有项目保护 | 已有规则、交接与长期记录保留；已有当前任务表时不再塞入示例任务 |
| 脚本与旧配置迁移 | 预览不写；执行后同步同名旧协议脚本，仅清理声明废弃的顶层 `mcp` 键，保留已有正文 |
| MCP 标准输入输出 | 子进程实测握手、列出 5 工具、正确项目的状态与校验、默认接入预览不写；没有连接实际 AI 宿主 |
| Python 3.10 语法检查 | 全部 Python 脚本按 3.10 语法解析通过；**不是在 Python 3.10 解释器上运行测试** |
| 内容与文件清单检查 | 检查私人用户名/项目关键词、常见密钥形状、本地文档链接，以及缓存、备份、日志、ZIP、符号链接和 Git 历史是否误带 |
| 目标路径翻译回归 | 通过；11 组覆盖 Windows 原生、WSL 与其他 Linux 三种宿主，以及真入口的 `--dry-run` |
| 钩子契约文档 | 已按脚本实际读取的字段与输出逐条核对，含最小接法与已知坑 |

内部自检与真实项目验收不同：工具目录不是一个正在工作的已接入项目，在其根目录直接运行 MCP 自检可能打印“缺少当前任务表”的问题计数，但仍通过服务内部自检。真正的项目应另运行 `validate_handoff`，确认 `passed: true`，并查看问题清单；不要只看进程退出码。

这些检查不是完整的保密审计，也没有证明所有可识别写入均无误。测试脚本使用失败场景时可能打印预期守卫提醒，应以对应断言与退出码判断。
