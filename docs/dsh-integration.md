# 可选：DSH 自动提醒与交接检查的接入边界

这一页给维护集成的人看。第一次使用建议先完成[普通接入](<quickstart.md>)；不必为了使用交接文件先安装 DSH 事件桥。

## v0.1.0 包含什么、不包含什么

包含通用的[启动提醒脚本](<../scripts/protocol_context.py>)、[交接守卫](<../scripts/protocol_guard.py>)、[项目分发器](<../scripts/protocol_dispatch.py>)和[适配器检查脚本](<../integrations/dsh/verify-hooks-adapter.cjs>)。

**不包含一份能让任何 DSH 用户直接启用的自动安装包。**本地使用环境需要修补的第三方 `hooks-adapter@0.1.0`，其补丁尚未核实上游来源和再分发许可，因此没有放进公开仓库。本机 `hooks.json`、`protocol-hooks.mjs`、旧的自制 root 适配层、私人 profile 和带个人路径的全局命令也没有复制。

单独运行检查脚本不会安装适配器，也不会补齐缺失的事件桥。

## 必须保留的安全提醒

**事件桥启动的外部命令以宿主用户身份执行，不当然继承模型文件工具的会话沙箱。**如果会话限制了可读写目录，不代表 hook 启动的 Python 也受到同样约束。启用前应检查脚本来源、命令和所有目标路径，不要对不可信项目全局启用高权限命令。

不要公开真实会话日志、凭据、个人 profile 或私人项目记录。守卫临时状态也可能含交接文本和路径，并非只有文件名。

## 接线需要实现的三件事

| 时机 | 应调用什么 | 要保证什么 |
|---|---|---|
| 会话开始 | `protocol_dispatch.py`，stdin 事件为 `SessionStart` | 在模型开始处理请求之前，完成并注入简短当前任务表 |
| 工具执行后 | `protocol_dispatch.py`，stdin 事件为 `PostToolUse` | 传完整工具参数、成功或失败结果、工具目标项目和会话标识 |
| 回合准备结束 | `protocol_dispatch.py`，stdin 事件为 `Stop` | 支持守卫的阻塞语义，要求 AI 补交接，而不是只打印一条无人读取的日志 |

分发器根据事件里的工作目录寻找项目配置，只对已配置的项目调用该项目自己的脚本。**分发器本身是工具目录/profile 级入口，不在接入脚本的七个项目运行时脚本同步清单里**；不要假设目标项目已安装或更新了分发器。项目里的脚本是独立副本，更新工具目录不会同步所有已接入项目。

本地曾使用的 DSH 事件关系是：`agent/created` 对应开始提醒、`tools/post-execute` 对应工具后检查、`agent/turn-stopping` 对应结束检查。它依赖适配器正确等待启动注入、提供合规的注入来源以及传递完整工具参数，**不能推断今后的所有 DSH 版本都相同**。

该 DSH Stop 桥不把守卫的 `systemMessage` 注入模型上下文。因此，一次补救和收尾要求放在首次 `block.reason` 内；后续一次警告另写 stderr，供宿主诊断日志记录，不能假定模型看到了它。`stop_hook_active` 即使被桥固定为 `false`，守卫仍自行限制次数；传入 `true` 则首次也不阻塞。详细语义见[钩子契约](<hooks.md#一次补救与状态保留>)。

Windows + WSL 组合还需要把宿主项目路径正确转成 WSL 可见路径。命令通常通过 `wsl.exe -d <发行版> -u <Linux用户>` 启动，再执行绝对路径的 Python 脚本；这些占位符不是可直接运行的命令。

[模板事件配置](<../templates/.codex/hooks.json>)只是项目模板中的接线示例，会随接入脚本复制到目标项目。它的存在**不证明 Codex 或其他宿主会自动读取或支持该格式**；本轮没有验收这些宿主，不把文件夹名字当兼容性保证。

## 已安装兼容适配器时的局部检查

仅在你已经有兼容的适配器、对应全局命令配置和一个已接入的试验项目时，才可以使用下面的检查。Windows Node 示例中的每个路径都需要替换：

```powershell
node "C:\path\to\agent-protocol\integrations\dsh\verify-hooks-adapter.cjs" `
  "C:\path\to\dsh-profile" `
  "C:\path\to\hooks.json" `
  "\\wsl.localhost\DISTRO\home\USER\projects\test-project"
```

这个脚本导入目标 profile 中已安装的适配器，模拟三个事件并执行已配置的命令；**不是纯静态检查**。只能对可信命令和一次性项目运行。通过时只说明这个适配器与配置的局部行为符合断言，不是 GUI、真实模型回合或完整安全隔离的验收。

本轮未执行这个检查，也没有改动当前 DSH 配置或重启应用。

## 真实环境仍需验收

至少检查：

1. 新开会话时，模型真正收到正确项目的简短任务表，而不是另一个项目的记录。
2. 改一个配置中列为重要的试验文件但不补交接，结束前应提醒或阻塞。
3. 在该次改动之后更新详细交接和当前任务表，再结束应放行。
4. 终端 Python 写交接时，成功且可识别的文本变化被认可；失败命令、`touch` 和未变文本不被当作完成。
5. 多会话同时工作时，成员交接走负责人签收，不由其他会话的偶然修改替代。
6. 同一会话连续缺口最多一次阻塞、一次警告、随后静默；改文件、普通工具事件或新的重要修改 token 不恢复额度。首次补正仍有缺口时应报告并结束，pending 保留；真正无缺口的结束检查后，同会话新工作才重新有一次机会。

**最新模板已有隔离回归记录，v0.1.0 公开仓库的复测结果另见[验证记录](<verification.md#v010-发布验收2026-10-31>)；没有完成最新真实 DSH GUI/模型回合验收。**当前识别范围包括常见直线内联 Python 和小型交接文本变化；动态脚本、控制流和未知工具事件不在全面识别承诺内。核心能力与限制见[边界](<../README.md#边界>)。
